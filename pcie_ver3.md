## MODEL ✨

### 1. 왜 지금은 반드시 필요하지 않은가?
현재 구조에서는 Express 서버가 데이터를 직접 읽어서 HTML(EJS)을 완성해 브라우저에 던져줍니다. 데이터와 화면이 하나로 묶여 있기 때문에, 별도의 통신 규약(API) 없이도 서비스 운영이 가능합니다.

---

### 2. RESTful API 도입 시 얻는 핵심 이점

#### ① 프론트엔드와 백엔드의 완전한 분리 (Decoupling)
*   **이점:** 서버는 오직 **데이터(JSON)**만 제공하고, 화면은 React, Vue와 같은 현대적인 프론트엔드 프레임워크나 단순 HTML/JS가 담당합니다.
*   **프로젝트 적용:** 화면 디자인을 전면 수정하더라도 백엔드 코드를 건드릴 필요가 없으며, 개발 효율이 올라갑니다.

#### ② 플랫폼 확장성 (Multi-Platform Support)
*   **이점:** 웹 서비스뿐만 아니라 **모바일 앱(iOS, Android), 데스크톱 위젯, 혹은 다른 웹사이트**에서도 동일한 메인보드 데이터를 가져다 쓸 수 있습니다.
*   **프로젝트 적용:** 나중에 "PCIe 레인 체크 모바일 앱"을 만들고 싶다면, 이미 만들어둔 RESTful API에 접속하기만 하면 됩니다.

#### ③ 외부 서비스와의 연동 및 생태계 구축 (Interoperability)
*   **이점:** 다른 개발자나 커뮤니티가 당신의 데이터를 활용할 수 있게 오픈 API를 제공할 수 있습니다.
*   **프로젝트 적용:** "다나와"나 "퀘이사존" 같은 사이트의 유저 스크립트가 당신의 API를 호출해 상품 페이지 옆에 자동으로 레인 공유 정보를 띄워주는 식의 확장이 가능해집니다.

#### ④ 유지보수 및 테스트 용이성
*   **이점:** 화면 없이 데이터 로직만 따로 테스트하기 쉬워집니다.
*   **프로젝트 적용:** Gemini AI를 통해 분석된 데이터가 정확한지 API 레벨에서 자동으로 검증하는 툴을 만들기 쉬워집니다.

### 요약: 언제 도입해야 할까요?

*   **현재처럼** 혼자서 빠르게 웹 도구를 완성하고 싶다면 **EJS(SSR)** 방식이 가장 빠르고 간단합니다.
*   **만약** "이 데이터를 다른 앱에서도 쓰고 싶다"거나, "더 역동적인 UI(React 등)를 만들고 싶다", 혹은 "내 데이터를 남들이 검색할 수 있게 개방하고 싶다"면 **RESTful API** 도입이 필수적입니다.

이 프로젝트의 경우, **Gemini AI 분석 기능**을 API 형태로 만들면 나중에 다른 프로그램에서도 "설명서 텍스트를 보내면 JSON을 돌려받는" 독립적인 도구로 활용할 수 있어 매우 유용할 것입니다.

## MODEL ✨

RESTful API를 도입한다면, 자원(Resource)을 중심으로 다음과 같이 API 경로와 메서드를 설계할 수 있습니다.

### 1. 메인보드 자원 (Motherboards)
사용자가 보드 목록을 보고 상세 정보를 확인하는 핵심 리소스입니다.

| 메서드 | 경로 | 설명 |
| :--- | :--- | :--- |
| **GET** | `/api/motherboards` | 전체 메인보드 목록을 가져옵니다. (검색 쿼리 지원: `?q=B650`) |
| **GET** | `/api/motherboards/:id` | 특정 메인보드의 슬롯 구성 및 레인 공유 규칙 정보를 가져옵니다. |
| **POST** | `/api/motherboards` | **[관리자]** 새로운 메인보드 데이터를 시스템에 등록합니다. |
| **PUT** | `/api/motherboards/:id` | **[관리자]** 기존 메인보드의 정보나 공유 규칙을 수정합니다. |
| **DELETE** | `/api/motherboards/:id` | **[관리자]** 특정 메인보드 데이터를 삭제합니다. |

### 2. AI 분석 및 유틸리티 자원 (Analysis & Tools)
매뉴얼 분석과 같이 특정 작업을 수행하는 기능적 엔드포인트입니다.

| 메서드 | 경로 | 설명 |
| :--- | :--- | :--- |
| **POST** | `/api/analyze/manual` | 메인보드 설명서 텍스트를 전송하여 Gemini AI가 추출한 JSON 결과를 반환받습니다. |
| **GET** | `/api/chipsets` | 시스템에서 지원하는 칩셋 목록(B650, X670 등)을 가져옵니다. (필터용) |

---

### RESTful API 설계의 특징 및 이점 예시

1.  **검색 기능의 통합:**
    *   `GET /api/motherboards?chipset=B650&brand=asus` 와 같은 방식으로 클라이언트가 원하는 데이터만 정교하게 요청할 수 있습니다.
2.  **데이터의 구조화:**
    *   응답은 항상 일정한 JSON 구조로 내려오므로, 웹뿐만 아니라 모바일 앱에서도 이 API를 그대로 호출하여 화면을 그릴 수 있습니다.
    *   *예시 응답:*
        ```json
        {
          "status": "success",
          "data": { "id": "b650-strix", "name": "ASUS B650...", "sharingRules": [...] }
        }
        ```
3.  **작업의 분리:**
    *   `POST /api/analyze/manual`을 호출해 AI 분석 결과를 먼저 받은 뒤, 사용자가 내용을 검토하고 최종적으로 `POST /api/motherboards`를 호출해 DB에 저장하는 2단계 프로세스를 구축하기에 매우 적합합니다.

이와 같은 구조로 API를 먼저 설계해두면, 나중에 프론트엔드를 React나 모바일 앱으로 전환하더라도 백엔드 코드를 다시 짤 필요가 없다는 것이 가장 큰 장점입니다.
